# 开饭咯 · 验收手册

> 每次改动后按顺序跑一遍，全部通过再提交/部署。
> 自动化脚本依赖微信开发者工具的自动化端口。

## 1. 本地自检（不需要开发者工具）

```bash
node scripts/check-project.js
node scripts/smoke-cloud.js
npx -p typescript tsc --noEmit
```

| 脚本 | 覆盖内容 |
|---|---|
| `check-project.js` | JSON 合法性、页面四件套、WXML 标签配对、组件引用 |
| `smoke-cloud.js` | 假数据库跑完整云函数：初始化、菜品/分类 CRUD、排序、下单计价、库存、订单号递增、催单、取消、状态流转、许愿、爱心券并发、营业设置、菜单与定时滚动、订阅消息、内容安全 |
| `tsc --noEmit` | 小程序 TypeScript 类型检查 |

## 2. UI 回归（真实云环境）

先在开发者工具里打开自动化端口：

```bash
"D:/software/WX web/微信web开发者工具/cli.bat" auto --project "D:\Code\cook" --auto-port 9420 --lang zh
```

然后：

```bash
node scripts/ui-regression-1105.js ws://127.0.0.1:9420
```

覆盖：首页加载、搜索、推荐位图片分支、订单筛选与分组、订单详情轮询、催单按钮、再来一单、厨房加载/历史/备菜/近 7 天统计/今日清单复制、菜品编辑图片入口、购物车角标、帮我选、结算快捷备注、我的统计、分类管理增删。

## 3. mock 模式 UI 回归

把 `miniprogram/config.ts` 的 `USE_CLOUD` 改成 `false`，重新编译后：

```bash
node scripts/mock-ui-regression.js ws://127.0.0.1:9420
```

覆盖：首页/搜索、厨房菜品排序、分类管理、菜品模板添加、营业设置与今日公告、排菜单、订单列表。
跑完记得把 `USE_CLOUD` 改回 `true` 并重新编译。

## 4. 云端新动作验收

```bash
node scripts/cloud-acceptance-menu.js ws://127.0.0.1:9420
```

覆盖：管理员身份、每日菜单保存/生效/恢复默认、首页按菜单过滤、下单/催单/取消。

菜品数据补充（管理员账号，按需执行）：

```bash
node scripts/fill-dish-recipes.js ws://127.0.0.1:9420
node scripts/add-template-dishes.js ws://127.0.0.1:9420
```

前者给线上已有菜品补做法（只填空缺），后者把 19 道模板菜一键加进云端菜单。

## 5. 部署之后

1. 在上面的脚本全部通过后再部署 `cloudfunctions/api`
2. 部署成功后至少跑一次 `node scripts/cloud-call.js getMenuForDate '{"date":"2026-11-05","meal":"lunch"}'`
3. 真机检查一次订阅消息授权与送达（体验版即可）

## 已知限制

- 云开发免费套餐有每日数据库读写额度，额度用尽会报 `EXCEED_REQUEST_LIMIT`，次日 0 点重置。
- 厨房页每 25 秒静默刷新一次订单（只读未完成订单），长时间挂着仍会消耗读取次数。
- 微信侧偶发 `getCloudAPISignedHeader ret:1000 system error`，与代码无关，稍后重试即可。
