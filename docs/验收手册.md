# 开饭咯 · 验收手册

> 每次改动后按顺序跑一遍，全部通过再提交/部署。
> 自动化脚本依赖微信开发者工具的自动化端口。

## 1. 本地自检（不需要开发者工具）

```bash
node scripts/check-project.js
node scripts/smoke-cloud.js
npx -p typescript tsc --noEmit
```

| 脚本 | 覆盖内容 |
|---|---|
| `check-project.js` | JSON 合法性、页面四件套、WXML 标签配对、组件引用 |
| `smoke-cloud.js` | 假数据库跑完整云函数：初始化、菜品/分类 CRUD、排序、下单计价、库存、订单号递增、催单、取消、状态流转、订单评价与回复、许愿、爱心券并发、营业设置、菜单、周饭表与定时滚动、订阅消息、内容安全 |
| `tsc --noEmit` | 小程序 TypeScript 类型检查 |

## 5. 部署之后

1. 在上面的脚本全部通过后再部署 `cloudfunctions/api`
2. 部署成功后至少跑一次 `node scripts/cloud-call.js getWeekMenus '{}'` 和 `node scripts/cloud-call.js getMenuForDate '{"date":"2026-11-05","meal":"lunch"}'`
3. 真机检查一次订阅消息授权与送达（体验版即可）

## 已知限制

- 云开发免费套餐有每日数据库读写额度，额度用尽会报 `EXCEED_REQUEST_LIMIT`，次日 0 点重置。
- 厨房页每 25 秒静默刷新一次订单（只读未完成订单），长时间挂着仍会消耗读取次数。
- 微信侧偶发 `getCloudAPISignedHeader ret:1000 system error`，与代码无关，稍后重试即可。
