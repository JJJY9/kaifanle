# 「开饭咯」点单小程序 · 产品与技术方案

> 版本 v0.2 · 2026-11-05
> 目标：先做一个给女朋友用的「家庭投喂」版，架构上预留对外商业化能力。
> 当前实现进度见 [迭代进度.md](迭代进度.md)，验收流程见 [验收手册.md](验收手册.md)。

---

## 0. 结论先行

1. **分两期做**：第一期私用（不上架、不支付、不涉及资质），第二期再考虑对外（需要个体户 + 食品经营许可证 + 微信支付）。
2. **形态**：微信小程序，原生开发 + 微信云开发，一个小程序内双角色（点单端 / 厨房端）。
3. **风格**：走**多巴胺潮玩 / 新丑风**——米白底 + 高饱和橙蓝黄 + 4rpx 黑色描边 + 硬投影 + 贴纸元素，像潮玩快闪店；靠粗描边和大字建立记忆点，靠菜品抠图色块统一质感。
4. **MVP 约 3 周**（业余时间）：菜单、点单、订单状态、订阅消息、厨房接单、许愿池。
5. **成本**：云开发 19.9 元/月（新环境前 6 个月免费）；私用阶段可以不认证。对外阶段再投入执照、许可证和 300 元/年认证。

## 1. 产品定位

### 1.1 一句话

**一个只有一口锅的「私厨点单」小程序：她点单，你接单，饭好了通知她。**

### 1.2 两阶段策略

| | 阶段一 · 投喂模式（私用） | 阶段二 · 小店模式（对外） |
|---|---|---|
| 用户 | 女朋友（+ 少量家人朋友） | 大众 |
| 发布方式 | 体验版，不上架 | 正式上架 |
| 备案 / 认证 | 不需要 | ICP 小程序备案必需；认证 300 元/年 |
| 支付 | 不做支付，家庭模式「记你账上」 | 微信支付（需个体户 / 企业主体） |
| 资质 | 无 | 营业执照 +《食品经营许可证》+ 餐饮类目 |
| 目的 | 好玩、好用、练手 | 真做生意 |

**为什么必须分期**：个人主体小程序既开不了普通微信支付，也选不了餐饮类目；而餐饮类目需要《食品经营许可证》，家庭厨房通常不满足商用厨房条件。所以「给女朋友用」和「卖给大众」在合规上是两个完全不同的产品，没必要为了后者拖慢前者。

阶段一代码里预留：用户表、价格字段、订单金额、支付回调位置、隐私协议页面——阶段二接支付和资质时不用重构。

### 1.3 差异化（对比大众外卖）

大众点单小程序解决「效率」，我们解决「被投喂的仪式感」：

- **许愿池**：她想吃什么可以许愿，你一键「安排」进菜单
- **餐次预约**：提前点明天的早餐、后天的晚餐
- **厨房状态直播**：锅已热 → 正在炒 → 出锅啦
- **爱心券**：洗碗券、奶茶券、夸夸卡
- **家庭模式**：不显示「支付」，显示「记你账上 ♥」

提炼出的通用骨架：

```
首页（营业状态 + 分类 + 商品）
  → 菜品详情 / SKU 弹层
  → 购物车
  → 结算（餐次 / 时间 / 用餐方式）
  → 订单状态时间轴
  → 订阅消息触达
```

这套骨架是十年验证过的，不用发明新流程，差异只做在内容和气质上。

## 3. 用户与场景

### 3.1 角色

**A · 点单的人（女朋友）**
- 早上 9 点，想中午吃什么
- 晚上 10 点，预约明天的早餐
- 想吃什么但不好意思直说 → 许愿池
- 临时想吃、看今天有什么 → 首页「今日菜单」

**B · 掌勺的人（你）**
- 早上看今日订单，决定买什么菜
- 做饭过程中更新状态，让她知道进度
- 某道菜卖完了，一键下架 / 售罄
- 收到她的小心愿，决定哪天安排

**C · 大众用户（阶段二）**

### 3.2 关键旅程

**她点一顿饭：**
打开小程序 → 看到「今日营业中 · 午餐供应到 11:30」→ 浏览菜单 → 加购 → 选餐次和期望时间 → 备注「少辣」→ 下单 → 收到「已接单」通知 → 收到「出锅啦」→ 吃饭。

**你接一单：**
打开厨房 tab → 看到今日 2 单 → 接单 → 备菜中 → 出餐 → 一键通知。

**她许一个愿：**
许愿「想吃番茄牛腩」→ 你收到 → 点「安排到周四晚餐」→ 周四菜单自动出现，她打开就能看到。

## 4. 功能规划

优先级：P0 = MVP 必做，P1 = V1.1，P2 = 阶段二或以后。

### 4.1 点单端

| 模块 | 功能 | 优先级 |
|---|---|---|
| 首页 | 营业状态、日期问候、餐次切换（早 / 午 / 晚）、分类锚点、菜品卡（图 / 名 / 一句话描述 / 价格或爱心值 / 标签 / 售罄态）、今日推荐大图 | P0 |
| 菜品详情 | 大图、描述、辣度 / 份量 / 加料规格、备注 | P0 |
| 购物车 | 底部悬浮购物车、数量增减、清空 | P0 |
| 结算 | 餐次、期望时间、用餐方式（在家吃 / 送到你处 / 自取）、备注 | P0 |
| 订单 | 列表、详情、状态时间轴、再来一单、未接单前可取消 | P0 |
| 订阅消息 | 下单成功、接单、出餐 | P0 |
| 我的 | 头像昵称（填写组件）、口味偏好 / 忌口、常用地址、历史订单 | P0 |
| 许愿池 | 提交心愿、查看状态（待安排 / 已安排）、许愿历史 | P1 |
| 爱心券 | 洗碗券、奶茶券、夸夸卡，可发放 / 兑换 | P1 |
| 预约日历 | 按天预约未来 7 天 | P1 |
| 每周菜单 | 提前看下周菜单并预点 | P1 |
| 分享 | 分享菜品卡片、菜单海报到聊天 | P1 |
| 投喂统计 | 本月吃了多少顿、最常点、照片回忆墙 | P2 |

### 4.2 厨房端（同一个小程序内，按 openid 白名单显示）

| 模块 | 功能 | 优先级 |
|---|---|---|
| 今日概览 | 待接单数、今日订单、今日菜单、份数与金额 | P0 |
| 订单处理 | 接单 / 拒单（带原因）/ 状态流转 | P0 |
| 菜品管理 | 上下架、售罄、库存份数、简版新增菜品 | P0 |
| 每日菜单编排 | 选择今天供应哪些菜、各餐次截止时间 | P0 |
| 许愿处理 | 查看心愿、一键「安排到某天」 | P1 |
| 数据看板 | 周 / 月订单量、复购、常点菜 | P2 |
| 小票打印 | 云打印机（易联云等） | P2 |

### 4.3 订单状态机

```
待接单 ──接单──▶ 已接单(锅已热) ──▶ 制作中(正在炒) ──▶ 待取餐(出锅啦) ──▶ 已完成
   │                                                    
   └──拒单/取消──▶ 已取消
```

- 展示文案可以可爱，底层状态枚举保持规范：`pending / accepted / cooking / ready / completed / cancelled`
- 每次状态变化写一条 timeline，前端渲染时间轴
- 状态变化触发订阅消息（她）

### 4.4 MVP 明确不做

- 不做多商户 / 平台、不做骑手配送、不做储值、不做复杂营销、不做 App / H5
- 不做实时 WebSocket，用订阅消息 + 下拉刷新即可
- 不做复杂推荐算法，「今日推荐」由你手动勾选

## 5. 视觉方案（重点）

### 5.1 方向

**「多巴胺潮玩 / 新丑风（Neo-Brutalism）」**：像潮玩快闪店，而不是外卖平台。

关键词：**高饱和 · 粗描边 · 硬投影 · 贴纸感 · 大字号**。

Mood 参考：泡泡玛特门店的色块、蜜雪冰城的亲切感、多巴胺穿搭的撞色、贴纸手账的拼贴感、快闪店海报的粗排版。

配色纪律（防止「花」）：**底色永远克制（米白），黑色描边统一全局，每屏最多 2 个强调色，贴纸不超过 3 个。**

### 5.2 色彩

| Token | 色值 | 用途 |
|---|---|---|
| `--bg` | `#FFFDF6` | 米白背景 |
| `--surface` | `#FFFFFF` | 卡片 |
| `--ink` | `#111111` | 文字 / 描边 / 硬投影 |
| `--ink-2` | `#5C5C5C` | 次要文字 |
| `--orange` | `#FF6B35` | 主按钮、加购、价格 |
| `--blue` | `#2D9CFF` | 餐次切换、信息、链接 |
| `--yellow` | `#FFD23F` | 标签、角标、高亮色块 |
| `--pink` | `#FF5C8A` | 爱心、许愿、促销 |
| `--green` | `#2FBF71` | 营业中、成功 |
| `--muted` | `#B8B8B8` | 售罄、禁用 |

配色纪律：

- 橙色只给「要点的按钮」，一屏只出现一次主 CTA
- 黄色配黑字，不配白字（对比度）
- 蓝色和粉色只做局部点缀，不铺大面积背景
- 售罄、禁用一律去色，不用彩色

深色模式放到 V2，先不做。

### 5.3 字体

- **标题 / 按钮**：得意黑 Smiley Sans（免费商用，粗斜切，自带潮玩感），通过 `wx.loadFontFace` 加载；备选站酷庆科黄油体（圆润可爱，免费商用）
- **正文**：系统默认（PingFang SC / HarmonyOS Sans）
- **价格 / 数字**：DIN Condensed / Bebas Neue，加粗
- **规则**：标题 52–64rpx、字重拉满、行高 1.1；正文 28rpx、行高 1.6；文案短、口语化（「干饭！」「明天赶早」「加一份？」）

### 5.4 布局与组件

- **卡片**：白底 + 4rpx 黑色描边 + 8rpx/8rpx 硬投影（`box-shadow: 8rpx 8rpx 0 #111`），圆角 40rpx
- **按钮**：pill 形 + 4rpx 黑描边 + 硬投影；按下时位移 8rpx、阴影消失，做出物理按压感
- **贴纸标签**：白底黑边，轻微旋转 -6°~6°，用于「今日推荐」「限量」「新品」「售罄」
- **菜品图**：白底或纯色底拍摄 → 抠图 → 放在橙 / 黄 / 蓝色块上，像贴纸；图框统一 4rpx 黑边
- **图标**：粗线条线性图标 + 少量手绘涂鸦（番茄、锅铲、爱心、星星）
- **分隔**：不用灰色细线，用黑色虚线或留白色块
- **装饰纪律**：每屏贴纸 ≤3 个、涂鸦 ≤2 个，让信息和按钮成为视觉主角

### 5.5 动效

- 加购：按钮按压回弹 + 数字徽章 pop（scale 1 → 1.3 → 1）+ 商品飞入购物车
- 购物车 bar：果冻位移 + 硬投影抖动
- 弹层：从底部弹性滑入（cubic-bezier 回弹）
- 下单成功：贴纸「开饭咯！」掉落 + 轻量纸屑动画
- 骨架屏：做成色块拼贴样式
- 下拉刷新：小锅贴纸拉伸
- 性能约束：描边 / 硬投影全部用 CSS，不切图片；动效只用 transform / opacity；首屏图片懒加载

### 5.7 反面清单（不要出现）

- 渐变糊满屏、奶茶色性冷淡（和潮玩方向相反）
- 一屏超过 2 个强调色、贴纸超过 3 个，变成「花屏」
- 用 emoji 当图标堆满界面（手绘贴纸可以，emoji 要克制）
- 3D 卡通人物、金粉霓虹、模板蓝
- 没有黑描边的「伪潮玩」——描边和硬投影必须统一
- 把品牌色用在正文文字上，牺牲可读性
- 营销弹窗、自动播放动效

### 5.8 品牌延伸（可选）

- **Logo**：粗描边的小锅 + 番茄卡通形象，带表情，可延伸成微信表情包
- **空状态 / 加载**：小锅贴纸的不同表情
- **分享海报**：贴纸拼贴 + 大标题 + 订单截图
- **周边**：贴纸、冰箱贴——很适合作为给女朋友的小礼物

## 6. 技术方案

### 6.1 选型对比

| 方案 | 适合场景 | 评价 |
|---|---|---|
| **原生小程序 + TypeScript + 云开发** | 只做小程序、个人维护 | ✅ 推荐：微信能力最全，无需服务器和域名，个人维护成本最低 |
| Taro 4 + React + 云开发 | 以后想同构 H5 / App | 可行，但构建链和调试成本更高 |
| uni-app + 自建后端 | 多端分发 | 小程序端体验和能力有折损 |
| NestJS + MySQL 自建 | 长期商业化、多商户 | 控制力最强，但要服务器、备案、运维，私用阶段没必要 |

### 6.2 推荐架构

```
小程序（TypeScript）
 ├─ pages/        点单端 + 厨房端
 ├─ components/   dish-card / sku-sheet / cart-bar / timeline / empty ...
 ├─ store/        mobx-miniprogram
 └─ services/     云函数调用封装
        │ wx.cloud.callFunction
        ▼
微信云开发
 ├─ 云函数：createOrder / updateStatus / getMenu / toggleDish / handleWish ...
 ├─ 云数据库：users dishes categories menus orders wishes coupons
 ├─ 云存储：菜品图片
 ├─ 定时触发器：每日 05:00 生成今日菜单
 └─ 订阅消息：下单 / 接单 / 出餐
```

不需要自建服务器，开发阶段也不需要域名；只有**正式上架时**才需要做小程序 ICP 备案（阶段二）。

### 6.3 关键技术决策

- **渲染**：默认 WebView 渲染；首屏性能有要求再考虑 Skyline，不混用省坑
- **状态管理**：mobx-miniprogram（轻量，官方生态）
- **UI**：自研 design tokens + 少量 TDesign Weapp 兜底弹窗 / 日期选择
- **角色**：`users.role = admin | customer`，admin 的 openid 写在云函数白名单；厨房 tab 前端隐藏 + 云函数校验（双保险）
- **安全**：数据库安全规则最小权限；所有写操作走云函数；备注 / 许愿内容过 `msgSecCheck`
- **库存**：云数据库原子操作 `inc`；下单时实时校验售罄
- **订阅消息**：一次性订阅，下单时同时申请「接单通知」；管理员申请「新订单通知」
- **图片**：上传前 `wx.compressImage` 压缩，存云存储；菜品图统一白底拍摄后抠图，色块背景用 CSS 实现
- **视觉实现**：描边 / 硬投影全部用 CSS（border + box-shadow），不切图片；得意黑通过 `wx.loadFontFace` 加载，失败时回退系统粗体
- **分享**：`onShareAppMessage` 带菜品 id 深链；海报用 canvas（P1）
- **隐私**：使用头像昵称填写组件；手机号非必需；隐私协议页面 P0 就要有

## 7. 合规与上架路线

### 7.1 阶段一（私用）

1. 注册**个人主体**小程序（免费），拿到 AppID
2. 开通云开发，开始开发
3. 用**体验版**给女朋友：把她加为体验成员，扫码即用
4. 不上架 → **不需要 ICP 备案，也不需要认证**
5. 体验成员名额有限（几十人），家庭使用完全够

注意：体验版二维码长期有效；每次上传新版本后，她重新打开小程序即可看到新版。

即使用于私用，也建议把备注、许愿接入 `msgSecCheck`，成本极低，养成好习惯。

### 7.2 阶段二（对外）——顺序很重要

1. 办理**个体工商户**（多数城市线上免费，1–3 天）
2. 取得**《食品经营许可证》**（需要符合要求的经营场所；家庭厨房通常不满足，可考虑共享厨房 / 小店面；部分省份有「小餐饮登记」通道）
3. 用个体户主体注册小程序（或走主体变更，保留 AppID 和代码，以微信最新规则为准），类目选「餐饮服务」
4. 微信认证（300 元/年）
5. 完成小程序 ICP 备案（免费，1–20 个工作日）
6. 开通微信支付（费率 0.6%）
7. 提交代码审核 → 上架
8. 上线后补齐：隐私保护指引、内容安全、售后与食品安全责任

**风险提示**：家庭私房菜无证对外售卖属于违规经营；挂靠资质有法律风险，不建议。如果暂时没有实体店，可以先把阶段一做成产品 Demo / 作品集，或者走「菜单展示 + 微信联系」的轻模式（但只要对外经营食品，本身仍需要资质）。

### 7.3 另一种阶段二：工具型产品

如果不想自己卖饭，也可以把产品做成**给已有资质的小餐馆用的点单工具**（商家用自己的主体和许可证上架）。这是另一个产品方向，本期只做技术预留，不展开。

## 9. 命名与品牌

候选名称：

- **开饭咯**：口语化、有能量，跟潮玩气质最搭（推荐）
- 饭搭子：有梗、传播性强，但名称可能已被占用
- 投喂一下：情侣语境很贴，但对外用略窄
- 今天吃啥：直接、好记，名称大概率被占用

- 英文副标：Let's Eat / Feed Me
- Slogan：「今天想吃啥？」或「她点单，你掌勺。」
- Logo 方向：粗描边的小锅 + 番茄卡通形象，带表情，可延伸成微信表情包
- 品牌性格：活泼、有梗、不装；文案说人话，偶尔自嘲

上架前要在微信公众平台查名称唯一性；个人主体名称不能含某些受限词。
